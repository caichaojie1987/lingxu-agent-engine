# 合规双层设计

对外（C 端/公网）场景的模型输出必须过内容合规。本引擎的做法：**词库驱动、双层执行、fail-safe**。

## 双层结构

```
模型输出 → [第一层：引擎出口 compliance.mjs] → [第二层：业务后端出口] → 用户
```

- **第一层（本仓库）**：public 场景的回答在引擎出口先过滤一遍；
- **第二层（业务后端）**：后端转发给用户前再过滤一次——防引擎被绕过/直连，也防两层实现漂移；
- 两层读**同一个 JSON 词库**（词库单一事实源），行为幂等：重复过滤结果不变。

## 词库格式

```json
{
  "version": "demo-1",
  "public_fallback": "这个问题涉及具体承诺，我这边不便直接答复。……",
  "rules": [
    {"word": "保证",   "action": "reject"},
    {"word": "免费",   "action": "replace", "replacement": "让利"}
  ]
}
```

- **reject**：命中 → 整段替换为 `public_fallback`（不泄露红线原文，答非所问是故意的：
  让模型学会绕开，而不是学会措辞绕词）；
- **replace**：命中 → 就地中性替换；
- `exempt`：豁免子串（如"保证书"不该被"保证"命中）；
- 环境变量 `COMPLIANCE_BLOCK_WORDS=a,b,c` 可临时追加 reject 词（词库已有则以其为准）。

## 行为细节

- 词库文件按 mtime 热加载，改词库不用重启；
- 词库**读不到时 fail-safe**：引擎侧放行但打告警——因为第二层（后端）仍强制；
  如果你是单层部署，请把 `COMPLIANCE_LEXICON_PATH` 指到存在的文件并在启动时检查；
- **public 场景禁用 SSE 流式**（见 `docs/scene-guide.md`）：delta 流无法做词级出口过滤；
- 合规命中会写进响应 `r.compliance = {action, reason}`，便于审计与调词库。

## 为什么是词库而不是分类器

垂直业务的红线词（承诺类、价格类、资质类）是运营口径，变化频率高于模型迭代——
用 JSON 词库让**运营改词库、工程不改代码**，且两层行为可精确复现。分类器可以作为
第三层加在业务后端，但不要替代词库：可解释、可审计、零延迟这三点词库无可替代。
